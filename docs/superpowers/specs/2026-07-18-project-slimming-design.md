# 三算法项目瘦身设计

## 目标

把当前分支收敛为渗流通道三算法工作区，只保留 SimPEG、FEniCSx 和 empymod 的最新实现、必要测试、报告工具与可复现配置。删除 COMSOL 算法及其集成面，删除旧 IP 任务和过渡运行产物，并把当前晚期 `Ex` 未验证问题如实固化。

## 保留边界

- SimPEG 渗流通道背景场、异常体响应和差异响应代码及 YAML 配置。
- FEniCSx 完整三维全域求解、对称网格生成、接收器采样和磁场恢复代码；不得改回单侧求解再镜像。
- empymod 分层背景参考与三算法对比接口。
- 渗流通道验证矩阵、汇总、绘图和 Word 报告生成工具。
- 直接覆盖上述主链的单元测试、契约测试和轻量级 smoke 测试。
- 一份当前状态说明，明确晚期 `Ex` 空间收敛未通过，不能宣称完整内部验证。

## 删除边界

- `COMSOL/`、COMSOL Python/Java/CLI、COMSOL 测试，以及四算法聚合接口。
- 独立 `sotem_ip/`、IP 专用实现、样例、测试和与当前无关的旧诊断入口。
- `dolfinx/current_task_runs/` 全部已跟踪运行输出；原始大结果继续由 `.gitignore` 排除。
- 旧研究阶段计划、重复进展报告、缓存、临时目录和过时生成物。
- 已确认干净的本地 COMSOL 专用工作树和本地分支，但仅在当前精简分支成功推送后删除。

## 当前科学状态

均匀半空间与早期强信号区的一致性不能证明异常体晚期响应正确。当前 Rx4/Rx5 的晚期 `Ex` 对空间离散和接收器恢复敏感，尚未形成稳定空间收敛序列。因此仓库只保留“当前计算进展”，不把它标记为已完成的科学验证。

## Git 策略

只删除当前分支 HEAD 中的内容，不重写历史，不强制推送。旧提交仍可恢复 COMSOL 代码。目标分支为 `codex/seepage-channel-verification`，推送至现有 `origin`。

## 验收标准

1. 当前树不存在 COMSOL 算法文件、导入或运行入口。
2. 当前树不存在 `sotem_ip` 和 `dolfinx/current_task_runs`。
3. SimPEG、FEniCSx、empymod 渗流通道主文件和配置均存在。
4. 当前状态文档明确记录晚期 `Ex` 未验证。
5. 保留测试全部通过，Python 文件可编译，Git 工作树在提交后干净。
6. 分支成功推送；不创建或执行 Git 历史重写。
