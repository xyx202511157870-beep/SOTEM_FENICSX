# SOTEM FEniCSx 算法仓库清理与中文化发布设计

## 1. 目标

将当前最新的 `codex/zhou2020-strict-validation` 算法快照整理为一个独立、可安装、可测试、以中文说明为主的公开仓库，并更新到：

```text
git@github.com:xyx202511157870-beep/SOTEM_FENICSX.git
```

本次发布只整理代码、依赖、模型配置、示例和自包含测试，不重新计算昂贵的三维正演结果，也不把本地计算产物作为“算法通过”的替代证据。

## 2. 发布策略

采用“保留 Git 历史、清空当前文件快照”的方式：

1. 从最新严格验证分支建立独立发布分支；
2. 删除远端当前快照中与算法发布无关的文件；
3. 在发布分支完成中文化、依赖修正和测试；
4. 将验证后的发布分支直接推送到远端 `main`；
5. 不使用孤立分支，不强制删除历史，因此旧内容仍可从 Git 历史恢复。

远端 `main` 当前提交 `1d563637` 是发布来源分支的祖先，正常情况下可以快进更新，不需要强制推送。

## 3. 发布目录

最终仓库只允许保留以下内容：

```text
.
├── .gitignore
├── LICENSE
├── README.md
├── pyproject.toml
├── src/atem3d/
├── dolfinx/
├── sotem_ip/
├── benchmarks/
├── examples/
├── scripts/
└── tests/
```

各目录职责如下：

- `src/atem3d/`：通用电磁场、SOTEM、极化、接收器和验证基础库；
- `dolfinx/`：FEniCSx 三维时域有限元求解入口、网格、时间推进和运行管线；
- `sotem_ip/`：TEM-IP 极化模型与相关计算模块；
- `benchmarks/`：可复现模型参数、公开文献基准和参数来源；
- `examples/`：不依赖本机绝对路径的最小运行示例；
- `scripts/`：仅保留被算法、示例或自包含测试实际调用的工具；
- `tests/`：不依赖本机 `output/` 或 `generated/` 目录的测试。

## 4. 删除范围

最终发布快照删除以下内容：

- `output/`、`outputs/`、`generated/`、`.tmp/`、`tmp/`和缓存；
- 网格、场数据、检查点、日志和本地运行证据包；
- Word、PDF、图片资产和论文草稿；
- `IMPLEMENTATION_REPORT.md`；
- `TASK_BOOK_STATUS.md`；
- `deep-research-report.md`；
- `assets/`；
- `docs/`中的内部设计、执行计划和过程记录；
- 仅用于生成 Word、论文插图或本地证据包的脚本及其测试；
- 本机绝对路径、临时路径、工作树路径和环境残留；
- 不属于算法运行依赖的历史报告。

如果某个 `scripts/` 文件被运行入口或保留测试导入，则保留；否则删除。采用依赖扫描决定，而不是按文件名猜测。

## 5. 中文化规则

### 5.1 必须中文化

- `README.md`；
- 安装、环境、运行和参数说明；
- 核心模块级说明；
- 关键公式和数值步骤的代码注释；
- 用户可操作的错误排查说明；
- 示例配置中的解释性注释。

### 5.2 核心代码注释重点

以下位置必须加入或完善中文注释：

- 接地电性源与有限长导线源离散；
- DC 关断前初始场；
- Nédélec \(H(\mathrm{curl})\) 边元；
- 后向 Euler、BDF2 等时间推进；
- Cole–Cole 复电阻率/复电导率约定；
- 广义 Debye 拟合和记忆变量初值、更新；
- \(H_z\)、\(B_z\)、\(dB_z/dt\) 接收算子；
- Biot–Savart 积分及符号、单位约定；
- 网格、边界、时间步和误差门槛；
- empymod、SimPEG 与 FEniCSx 的量和坐标对齐。

### 5.3 保持英文

以下内容保持英文，避免破坏兼容性：

- Python函数名、类名、变量名和模块名；
- 命令行参数；
- FEniCSx、PETSc、MPI、Gmsh、SimPEG和empymod公共接口；
- 文件格式字段和已有JSON/YAML键；
- 国际通用物理量缩写。

不机械翻译每一个测试断言，也不为了中文化重写已经验证的数值公式。

## 6. 安装与依赖

发布仓库必须能在本机实际使用的WSL2 FEniCSx环境中运行：

```text
/home/paidaxin/miniconda3/envs/fenicsx
Python 3.10.20
```

当前 `pyproject.toml` 声明 `Python >= 3.11`，与实际FEniCSx环境冲突，导致 `pip install -e .`失败。发布前必须统一版本约束，至少支持Python 3.10，并验证可编辑安装。

Word报告依赖 `python-docx`不属于最终算法依赖。删除Word报告生成器和相应测试后，不应把 `python-docx`加入核心依赖。

## 7. 测试设计

### 7.1 当前基线

原始最新分支共收集1869项测试：

- 19项失败；
- 其中18项依赖未跟踪的本地 `generated/` 或 `output/`证据包；
- 1项因项目未安装且子进程没有 `PYTHONPATH`而失败；
- 这些失败不能在公开仓库中被描述为“全部测试通过”。

排除本次明确删除的本地证据审计、制图和Word报告测试后，核心算法测试集在：

```text
PYTHONPATH=<仓库>/src
```

条件下完成且退出码为0。

该核心测试集共收集1753项，执行结果为1749项通过、4项跳过、0项失败。

### 7.2 发布门槛

发布前必须满足：

1. `pip install -e .`在WSL FEniCSx环境中成功；
2. 保留测试全部通过，允许明确记录的可选依赖跳过；
3. `python -m atem3d.initial_field_diagnostics_cli --help`成功；
4. 主求解入口能够解析公开基准配置；
5. 不重新运行大型三维正演；
6. 仓库中不存在依赖本机 `output/`或`generated/`的测试；
7. 不存在超过约定上限的大文件、模型产物、密钥或本机绝对路径；
8. Git状态干净，提交内容只包含允许目录。

测试结果只证明代码和内部数值管线在当前环境通过自动化检查，不代表现场工程验证已经完成。

README不得写入已经被当前证据否定的“所有模型均已严格通过”之类表述。

## 9. 远端更新与恢复

推送前执行：

1. 获取远端最新 `main`；
2. 确认远端提交仍为预期祖先；
3. 记录推送前远端提交ID；
4. 验证发布快照；
5. 将发布分支推送到 `origin/main`；
6. 再读取远端 `main`，确认其指向本次发布提交。

如果远端在执行期间被其他人更新，则停止推送，不覆盖未知更新。

由于保留Git历史，恢复时可以将 `main`重新指向推送前记录的提交，不需要从本地输出目录恢复。

- 最终目录符合允许清单；
- README及核心算法注释已中文化；
- 可编辑安装成功；
- 保留测试完整通过；
- 敏感信息和生成物扫描通过；
- 发布提交已经推送到远端 `main`；
- 远端提交ID与本地发布提交一致；
- 最终说明如实记录删除内容、测试数量、跳过项和未执行的大型正演。
